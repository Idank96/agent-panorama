**Date:** 2026-06-05
**Scope:** New `live/` package, `serve` CLI, frontend polling, static bundling, CI/publish updates.

## What was built

One-line LangChain/LangGraph integration that streams completed agent runs to a local
dashboard, updating live:

```python
from agent_panorama.live import PanoramaCallbackHandler
agent.invoke(inputs, config={"callbacks": [PanoramaCallbackHandler()]})
```

plus `agent-panorama serve --open` (requires `pip install 'agent-panorama[live]'`).

## AI Rationale

**Options considered and decisions (user-approved during planning):**
1. **Server stack** — FastAPI + uvicorn under a `[live]` extra vs. pure stdlib server.
   Chose FastAPI for maintainability; core deps stay minimal because the *handler* uses
   stdlib HTTP, so instrumented apps need only base agent-panorama.
2. **Update transport** — polling vs. SSE. Chose polling `/api/report` every 3 s:
   `build_report` is pure/cheap, payloads are KBs, and SSE can be layered on later.
3. **Granularity** — completed runs only vs. in-flight runs. Chose completed-only: no new
   "running" status needed anywhere; existing `Outcome` enum and frontend `Status`
   mapping unchanged. In-flight runs moved to the roadmap vision.
4. **UI shipping** — bundle the built Vite app as package data vs. JSON-only server.
   Chose bundling for the true "pip install → one line → open browser" UX.

**Trade-offs/learnings:**
- hatchling `force-include` collides with the tracked `static/.gitkeep`
  ("second file at the same path"); `[tool.hatch.build] artifacts` is the correct
  mechanism for gitignored build outputs.
- `npm run build` re-touches `.gitkeep` because Vite's `emptyOutDir` deletes it.
- The handler re-derives nothing: outcome/retries/anomalies/cost are computed
  server-side by the existing `analysis._enrich_run`, keeping live and batch semantics
  identical.
